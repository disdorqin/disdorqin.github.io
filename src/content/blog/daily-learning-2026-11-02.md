> **科研自动化专题学习笔记。** 本文参考一段真实 B站科研工作流教程：本地取得完整音频、290 条带时间戳的 ASR 字幕，抽取并复核了关键画面。还对照 MCP 官方文档及 Agent Skills 规范。ASR 有误听，视频里“效率翻倍、少走 99% 弯路”的营销说法也没有独立测量证据。

## 一、为什么科研需要工作流，而不是同时找五个 Agent 聊天？

看完视频最值得记住的一点，是它把一个科研任务贯穿始终：**问题与文献 → 创新方案 → 代码实验 → 评估 → 写作与复核**。如果每个步骤只剩几句聊天记录，没有输入、输出或检查标准，就算安装再多 Agent，也只是一个难以复现的演示。

视频约 **00:17–01:17** 展示了五层结构：科研任务流程、Agent 执行层、Skill 工具层、MCP 接口层、领域知识库。这里的层级是概念分工，不是说每一层必须单独部署服务。

![科研任务、Agent、Skill、MCP及知识库的五层结构](/learning-digests/2026-11-02/research-five-layers.svg)

*图 1｜基于视频结构独立重绘的概念图，不是直接截取原视频。真实系统中这些组件可以并列调用，不一定构成单向网络层级。*

五层分别回答不同问题：

- **任务流程**：研究目标是什么，什么时候应该停止，最终如何验收？
- **Agent**：下一步由谁做、调用哪个工具、遇到错误如何恢复？
- **Skill**：把成熟操作、规则、脚本和参考资料封装成可复用能力。
- **MCP**：通过标准接口连接不同工具、数据源和软件。
- **领域知识库**：为规划与判断提供可追溯的理论、论文、经验和反例。

需要区别：MCP 是外部能力连接协议，Skill 是技能包，RAG 是检索资料并辅助生成的方法。**三者并非相互替代的竞争框架。** 视频展示的是一种教学架构，不是这些标准的官方唯一架构。

## 二、知识库为什么不能简单堆论文？

视频 **01:17–03:12** 展示知识库中基础理论、论文、代码经验的分层，并希望研究助手引用这些材料后减少随意发挥。这一点很有价值：比起让模型每次从零猜测，能找到原始文献和适用条件更可靠。

但“知识库里全是百分百可信资料”的说法需要修正。论文不是因为来自某个期刊就自动正确，方法也不是一次实验成功就可以无条件推广。

一个更稳妥的知识库应该区分三种条目：**经充分验证的结论、尚待验证的研究假说，以及已知会失败的停止条件**。每条结论都尽量记录数据范围、可用输入、评价指标、时间条件和反例。

例如某方法在一个电力市场表现不好，我们不能立即推出它在其他能源市场也没用。只有比较数据条件、训练方式、评价口径之后，才能判断经验是否可以迁移。

## 三、MCP 接通了，为什么实验还可能错？

视频 **04:10–05:40** 建议打通常用研究软件的接口；MCP 的主要价值确实是减少重复开发工具连接的成本。但能调用程序，不等于调用到正确数据，更不等于得到合法科研结论。

假设一个流程必须依次成功完成：获得可靠文献、提取正确证据、执行合法实验、核验结果。记第 $i$ 步成功事件为 $S_i$，那么：

$$
P(S_1\cap\cdots\cap S_n)
=
\prod_{i=1}^{n}
P(S_i\mid S_1\cap\cdots\cap S_{i-1}).
$$

这是概率的**链式法则**，并未假设步骤独立。即使工具都能启动，端到端任务成功率仍可能被某个薄弱环节限制。因此要分别检查：接口连通性、输入正确性、运行结果、证据一致性。

比如代码运行成功，但使用了预测时刻之后才能获得的数据，那它对真实预测任务依然无效。此类错误不是 MCP 协议能代替你发现的。

## 四、优化 Skill，不等于给基础模型重新训练

视频 **07:05–09:20** 讨论 Skill 的迭代优化，还展示了目标函数、可调参数与修改规则。这个比喻很生动，却容易让新人误解。

修改技能说明、增加命令、积累回归案例，通常是在**优化外部流程和工具行为**；它并不自动构成神经网络的梯度训练。Agent Skills 公开规范要求每个技能至少有 SKILL.md，此外可按需提供脚本、参考文档和资源文件。

我认为一个可靠的 Skill 最少回答五件事：什么任务触发？允许读取什么？具体运行什么？如何判断产出正确？失败如何回退？这比写上万字“万能提示词”更实用。

## 五、怎样设计独立的证据门禁？

视频结尾 **09:20–10:15** 提醒把模糊的期望改为可检查指标。对任何准备公开的科研论断 $c$，可以设计一个简单的编辑门禁：

$$
g(c)=
\mathbb{1}\bigl[
\operatorname{source}(c)
\land\operatorname{support}(c)
\land\operatorname{scope}(c)
\bigr].
$$

source 表示有可定位的原始出处；support 表示该出处确实支持论断；scope 表示结论没有超出证据所涵盖的数据和场景。三个条件都检查通过，才把它标为有证据支持的陈述。

**这只是本文提出的工程审核规则，不是视频作者发表的新算法。** 对没有独立验证的观点，应标为“待核验假说”，不能因为附上链接就称作科学结论。

## 六、今天就能做的最小实验

从一个很小的任务开始：获取一篇公开论文 → 提取研究假设与实验设计 → 生成研究摘要 → 独立检查两条关键结论。

通过以后，再加入检索、自动运行实验、绘图和写作。每次多接一个环节，都记录输入、工具版本、产出、异常和检查结论。若失败，也尽可能保存复现步骤和停止条件。

**真正的完成标准不是 AI 自称“全部完成”，而是源材料、处理过程和最终结论均可以被重新核对。**
